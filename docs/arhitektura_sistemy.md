# Архитектура информационной системы

## Общая архитектура

Информационная система интернет-магазина построена по распределённой архитектуре и включает следующие основные компоненты:

- клиентский слой (Frontend);
- серверный слой (Backend);
- уровень хранения данных (Database);
- внешний платежный сервис (Payment Gateway).

Архитектура обеспечивает разделение пользовательского интерфейса, бизнес-логики, хранения данных и внешних интеграций.

---

## Компоненты системы

### Frontend Server

Frontend Server отвечает за взаимодействие с пользователем и предоставляет интерфейс оформления заказа (UI Checkout).

Основные функции:

- отображение каталога и корзины;
- ввод контактных данных покупателя;
- отображение статусов выполнения операций;
- отправка запросов на серверную часть системы.

Взаимодействие с Backend осуществляется через HTTP(S)-запросы.

---

### Backend Server

Backend Server содержит бизнес-логику процесса оформления заказа и координирует взаимодействие внутренних сервисов системы.

Основные компоненты:

| Компонент | Назначение |
|-----------|------------|
| A2 Controller | Обработка запросов оформления заказа и управление последовательностью операций |
| Cart Service | Работа с корзиной, получение и обновление данных товаров |
| Validation Service | Проверка корректности данных покупателя и заказа |
| Order Service | Создание заказа, изменение статусов и сохранение информации |

Backend выполняет следующие операции:

- обновление корзины;
- проверку данных заказа;
- формирование черновика заказа;
- подготовку заказа к оплате;
- обработку результата транзакции.

---

### Database Server

Database Server отвечает за хранение данных системы.

В базе данных хранятся:

- информация о товарах;
- данные о наличии;
- корзины пользователей;
- информация о заказах;
- данные покупателей;
- статусы обработки заказов.

Backend использует базу данных для чтения и записи информации в процессе оформления заказа.

---

### Payment Gateway

Payment Gateway представляет внешний сервис обработки платежей.

Основные функции:

- инициализация платежа;
- обработка транзакции;
- подтверждение результата оплаты;
- возврат идентификатора операции и статуса платежа.

---

# Взаимодействие компонентов

## Frontend → Backend

Frontend отправляет HTTP(S)-запросы для выполнения операций:

- начало оформления заказа;
- обновление корзины;
- передача данных покупателя;
- создание черновика заказа.

---

## Backend → Database

Backend выполняет операции чтения и записи:

- получение информации о товарах и наличии;
- сохранение корзины;
- создание заказа;
- обновление статусов после оплаты.

---

## Backend → Payment Gateway

Backend взаимодействует с платежным сервисом для:

- создания платежной сессии;
- получения результата транзакции;
- получения подтверждающих данных платежа.

---

# Сценарий работы системы

Процесс оформления заказа:

1. Покупатель взаимодействует с интерфейсом оформления заказа.
2. Frontend передаёт запросы на Backend.
3. Backend получает данные корзины и проверяет их актуальность.
4. Выполняется проверка данных покупателя.
5. Создаётся черновик заказа и выполняется подготовка к оплате.
6. Backend обращается к платежному сервису.
7. После успешной оплаты система обновляет статус заказа в базе данных.
8. Пользователь получает подтверждение оформления заказа.

---

# Диаграмма развертывания

Диаграмма развертывания отражает размещение компонентов системы на отдельных узлах:

- Frontend Server — пользовательский интерфейс;
- Backend Server — бизнес-логика и сервисы обработки заказа;
- Database Server — хранение данных;
- Payment Gateway — внешний сервис оплаты.

Такая структура позволяет разделить ответственность между компонентами системы и обеспечить возможность дальнейшего масштабирования.
